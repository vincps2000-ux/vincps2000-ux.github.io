USed this to gain a closer Look at how PDF files work:  https://www.docento.app/blog/pdf-internals-objects-and-streams

Essentially just a bunch of Objects marked with obj .. endobj

Structure:

Header : Version marker: (e.g. %PDF-1.3)
Body: just a List of Objects (e.g. <<
/ProcSet [/PDF /Text /ImageB /ImageC /ImageI]
/ExtGState <<
/Gs1 6 0 R
/Gs2 7 0 R
>>)
Cross-reference table: Offset of every object (e.g.
xref
0 23 (Number of Entries)
0000000000(offset) 65535(generation number) f(used(n) , not used (f)) 
0000136984 00000 n 
0000136935 00000 n

0000012590 00000 n

0000055589 00000 n

0000061178 00000 n 
0000061273 00000 n 
0000103026 00000 n 
0000103244 00000 n 
0000104821 00000 n 
0000135626 00000 n 
0000135849 00000 n )
Trailer: points to root object and xref (e.g. trailer
<<
/Size 23
/Root 2 0 R
/Info 16 0 R
>>
startxref
137055
%%EOF
)



PDF is read like this: reader goes to trailer, then xref table, and the xref table serves as an index of each object, allowing locating objects quickly.

Data is usually compressed in a Stream as binary, making it not readable.
